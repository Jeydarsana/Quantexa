0. READ THIS FIRST (Agent Instructions)

Build a complete, working, visually polished web application from the specification below.

The single most important rule in this brief: every number the app shows must be accompanied by plain English that a person with zero finance background can understand. A first-time user must be able to open this app, pick two things from two dropdowns, press one button, and immediately understand what happened and what it means — without knowing what a Sharpe ratio, a drawdown, or a backtest is.

If you ever have to choose between showing more data and making the meaning clear, choose clarity. Jargon is always allowed, but it must never appear alone — it must always be paired with a plain-English translation.

Do not stub features. Do not leave TODO comments. Every endpoint must return real computed values. Ship a seeded dataset so the app works instantly on first load even with zero network access.

Build order: (1) backend data layer + seed data, (2) asset taxonomy + quant engine, (3) plain-English explanation engine, (4) Strategy DNA, (5) backtest + portfolio simulation, (6) API routes, (7) frontend shell + theme, (8) pages one by one, (9) clarity + polish pass.

1. APP OVERVIEW

App name: QuantLens

One-line description: QuantLens lets anyone pick two types of assets, press one button, and get a clear, plain-English answer about how risky they are, how they behave, and whether a trading strategy would actually have worked — with every number explained in normal language.

Core problem it solves: Financial analysis tools are powerful but unreadable. They throw out numbers like "Sharpe 1.32, Max DD −24.6%, CAGR 11.4%" with no explanation, so only experts can use them. Meanwhile beginners are stuck with tools that are readable but shallow. QuantLens does both: real quantitative analysis underneath, plain English on the surface.

Target users (both must be served equally):

Beginner — a student or first-time user who has never heard of volatility. They need sentences, verdicts, and color-coded grades.
Expert — a quant researcher or finance student who wants the actual metrics, formulas, and trade ledger. They can switch on Expert Mode to see everything.

7.3 Data source & fallback

Primary: yfinance (free, no key).

python
df = yf.download(ticker, start="2015-01-01", end=None,
                 interval="1d", auto_adjust=True, progress=False)

Critical: Replit sandboxes often block Yahoo. The app must never error because of this. Resolution order in data_loader.py:

SQLite prices — if rows exist and the latest date is within 7 days, use them.
Else try yfinance with a 15s timeout inside try/except; on success upsert to SQLite.

7.7 Strategy definitions + plain descriptions

All strategies output a raw position series in {-1, 0, 1}. The backtester applies position = raw_signal.shift(1) before any P&L. Warm-up NaN rows are dropped first.

Strategy	Plain name shown in dropdown	Plain description	Rule
SMA Crossover	Trend crossover	Buys when the short-term average price rises above the long-term one, and sells when it falls back below. A classic "ride the trend" approach.	1 when SMA(fast) > SMA(slow), else 0 (or -1 if shorts on)
EMA Trend	Stay above the line	Buys when the price holds above a smoothed average for a few days in a row, and exits when it drops below.	1 when close > EMA(period) for confirmation_days consecutive days; exit 0 when close < EMA(period)
Momentum	Buy what's rising	Buys when the price is higher than it was a few months ago, betting that strength continues.	1 when close/close.shift(lookback) - 1 > threshold, else 0 (or -1 if shorts on and momentum < -threshold)
Mean Reversion	Buy the dips	Buys when the price falls unusually far below its recent normal, betting it bounces back.	Enter 1 when zscore(lookback) < entry_z; exit 0 when zscore >= exit_z. Stateful — carry the position forward
7.8 Exact formulas (implement these, do not improvise)
daily_return_t  = close_t / close_{t-1} - 1
log_return_t    = ln(close_t / close_{t-1})
cum_return_t    = (1 + daily_return).cumprod() - 1
ppy             = periods_per_year from the registry (252, or 365 for BTC-USD)
ann_volatility  = std(daily_return, ddof=1) * sqrt(ppy)
ann_return      = mean(daily_return) * ppy
CAGR            = (final/initial)^(ppy / n_obs) - 1
downside_dev    = std(daily_return[daily_return < 0], ddof=1) * sqrt(ppy)
sharpe          = (ann_return - rf) / ann_volatility        # rf default 0.02
sortino         = (ann_return - rf) / downside_dev
running_max_t   = cummax(equity_t)
drawdown_t      = equity_t / running_max_t - 1
max_drawdown    = min(drawdown)
calmar          = CAGR / abs(max_drawdown)
rolling_vol(w)  = rolling std(daily_return, w, ddof=1) * sqrt(ppy)
SMA(n)          = rolling mean of close over n
EMA(n)          = close.ewm(span=n, adjust=False).mean()
var_95          = 5th percentile of daily_return
cvar_95         = mean of daily_return below var_95
beta            = cov(asset, other) / var(other)
correlation     = Pearson on aligned daily returns (inner join on date)
zscore(n)       = (close - SMA(n)) / rolling std(close, n, ddof=1)

Risk Grade:

risk_score = 0.6 * clip(ann_volatility / 0.60, 0, 1)
           + 0.4 * clip(abs(max_drawdown) / 0.70, 0, 1)

< 0.15 → Very Low · 0.15–0.30 → Low · 0.30–0.50 → Moderate
0.50–0.70 → High · > 0.70 → Very High

Each grade carries a fixed plain sentence, e.g. Moderate → "Expect meaningful ups and downs, and be ready for a drop of around a quarter at some point."

7.9 Metric rating thresholds (drives the Good/Okay/Poor badge in §2.3)
sharpe:        > 1.0 good · 0.3–1.0 okay · < 0.3 poor
sortino:       > 1.5 good · 0.5–1.5 okay · < 0.5 poor
max_drawdown:  > -15% good · -15% to -35% okay · < -35% poor
ann_volatility:< 15% good · 15%–35% okay · > 35% poor
total_return:  > benchmark good · within ±5% of benchmark okay · else poor
win_rate:      > 55% good · 45%–55% okay · < 45% poor
profit_factor: > 1.5 good · 1.0–1.5 okay · < 1.0 poor
calmar:        > 1.0 good · 0.3–1.0 okay · < 0.3 poor
correlation, beta, skew, kurtosis → always "neutral"
7.10 Backtest engine rules (non-negotiable)
Execution price = next bar's open × (1 + slippage_bps/10000) for buys, (1 − slippage_bps/10000) for sells.
Transaction cost = notional × cost_bps / 10000, charged on entry and exit, deducted from cash.
shares = floor((equity × position_size_pct/100) / execution_price); remainder stays as cash.
equity_t = cash + shares × close_t. Record cash and invested at every bar so the cash chart is real.
Benchmark = buy-and-hold at the first bar's open with identical costs and slippage.
No leverage unless allow_short is on; shorts limited to 100% of equity notional.
A trade is recorded only when fully closed. An open position at the end is marked to market and flagged is_open: true.
Zero trades → return a valid result with an empty ledger, flat equity, verdict DO NOT PROCEED, and the plain sentence "This strategy never found a reason to buy during this period. Try a longer date range or different settings." Never a 500.
Two-asset blend: simulate each leg independently, combine equity by blend_weight, rebalance monthly.
7.11 Regime classification (plain names in the UI)

Using trailing data only:

Rising market (Bull): close > SMA(200) and rolling 60d return > 0
Falling market (Bear): close < SMA(200) and rolling 60d return < 0
Mixed (Neutral): everything else
Wild period (High Vol): rolling 20d annualized vol > 75th percentile of the full sample
Calm period (Low Vol): rolling 20d annualized vol < 25th percentile
Normal in between

Trend and volatility regimes are computed independently; the UI reports both in plain names.

7.12 Investment Verdict rule engine

Start score = 0. Every rule that fires produces a plain-English bullet citing its real number.

In favour (+): Sharpe > 1.0 → +2 · Sharpe 0.5–1.0 → +1 · beat buy-and-hold → +2 · shallower max drawdown than buy-and-hold → +2 · out-of-sample Sharpe ≥ 70% of in-sample → +2 · Monte Carlo prob_positive > 0.70 → +2 · win rate > 50% → +1 · profit factor > 1.5 → +1 · total costs < 10% of gross P&L → +1

Against (−): Sharpe < 0 → −3 · max drawdown worse than −30% → −2 · out-of-sample Sharpe < 50% of in-sample → −3 · prob_positive < 0.50 → −2 · fewer than 10 trades → −2 · costs > 25% of gross P&L → −2 · underperforms buy-and-hold after costs → −2 · Risk Grade "Very High" → −1

score >= 5      → PROCEED
score 0 to 4    → PROCEED WITH CAUTION
score < 0       → DO NOT PROCEED

Always show both lists, plus the one-sentence summary and the verbatim disclaimer from §3.3.
